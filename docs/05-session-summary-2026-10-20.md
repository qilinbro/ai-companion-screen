## 最终确认的目标

先做一个好看、可在 Windows 本地使用的极简桌面宠物 Demo。默认安静待机，主要元素只有可爱的 Dot 宠物；单击后展开小输入框，发出需求后才展开一张窄边框工作画布，角色留在角落。

用户输入自然语言，配置的模型判断是否需要查看当前屏幕，再调用相应工具。界面不要求用户选择“截屏”“翻译”“报错”等功能，也不依赖复杂提示词或前端关键词分类。当前采用兼容 OpenAI API 的 Chat Completions 服务，由用户在本机填写地址、模型名和密钥。

“帮我翻译一下当前页面”“我遇到了报错”是希望支持的交互场景。当前已实现向模型提供本次授权画面的基础链路；翻译、识图和报错原因判断依赖所选模型，终端自动修复尚未实现。

## 本次对话的主要决定

- 从补齐完整 Windows 产品，收敛为“完整交互 Demo + 可用的本地能力”，优先保证宠物、输入与工作画布体验。
- 减少次要元素，不采用常驻仪表盘、功能宫格、多列聊天或大量过程卡片。模型设置按需打开，工具名称和参数不铺在主界面。
- 保留原项目黑色角色及原动画，没有用新造型替换本机原角色。原素材仅本机学习使用；正式构建和便携包使用原创奶油色 DotPet。
- 用户提供了 [GPT Dot 功能介绍网址](https://blog.csdn.net/aidoudoulong/article/details/166886570)。参考来源及产品区分保留在[参考文档](02-product-references.md)，不把参考产品介绍写成本项目的完成清单。
- 最初讨论过本地截图与文字识别，随后明确收敛为提供屏幕工具，由大模型理解需求和画面。当前不做 OCR，不把本地规则路由当成模型理解。
- 模型服务类型已确认是“兼容 OpenAI API”。配置入口已实现，没有要求用户把密钥发到聊天里，也没有借用其他应用凭据。
- 界面采用黑白暖灰、窄边框、三点等待和流式光标。设计研究参考 assistant-ui、Vercel AI Elements，并使用已安装的 UI UX Pro Max 与 web-motion-design；引入情况见[第三方记录](third-party.md)。
- 根据后续反馈，修复了桌面拖动，并将原项目的动作与实际工作阶段对应。

## 已完成的当前功能

### 宠物与单画布

待机、折叠输入、工作画布在实现中分别使用 `idle`、`input`、`canvas` 三种窗口模式，仍保持“宠物 + 按需展开的一张画布”的产品结构。

单击宠物或按 `Ctrl+Alt+Space` 唤出输入；快捷键不可用时可从托盘唤出。支持文字发送、继续对话、流式显示、停止回复、复制和收起。输入处理包含中文输入法组合状态、空白与重复发送保护。只在请求实际进行时显示等待动画。

### 模型按需查看屏幕

桌面主进程调用用户配置的 Chat Completions 服务，接收实际增量文字和工具请求。目前唯一可由模型调用的工具是 `capture_screen`：

1. 需求先交给模型，普通文字问题可以直接回复。
2. 模型确实请求工具后，本机再次检查本次运行的屏幕授权、当前需求中的明确拒绝和工具参数。
3. 允许时获取一张真实主屏 PNG，临时隐藏本应用，画面留在内存。
4. 将工具结果及本次图像交给同一服务继续处理；等待图像分析时保持观察动作，收到实际文字后切换书写。
5. 本次画面可在对话中按需展开；后续会话历史只带有限近期文字，不自动重发旧图。

服务必须具备相应的流式、工具调用和图像输入能力。接口“兼容”不等于这些能力必然可用；真实服务及模型效果仍待验收。

### 配置与数据边界

- 服务地址、模型名和密钥在可信本地设置中填写。保存配置保留原需求，由用户再次发送，不自动启动请求。
- 密钥只在设置输入控件中短暂录入，经窄桥接交主进程管理，不进入普通对话、React 状态、日志、源码或构建。可选系统安全存储加密保存；不支持安全保存时没有明文回退。
- 更换服务不会沿用旧服务密钥。切换服务或模型会清理前后端会话，避免界面历史与实际上下文不一致。
- “允许模型查看当前屏幕”只在本次运行有效，界面说明画面会发送到所填服务；重启后默认关闭，修改服务或模型需重新勾选。
- 对话和截图不自动存盘，不写入 localStorage；模型只接收当前需求、有限文字上下文和本次获准的图像。
- 保留 Electron 隔离、沙箱、限制性 CSP、可信主窗口与主框架校验、最小 IPC。工具有限次调用并支持取消、超时及迟到事件隔离。

### 桌面拖动修复

原来只有宠物头顶一小块区域可拖动，身体只响应点击。现已改为按住身体拖动，保留单击展开；移动超过短按阈值后抑制随后的点击，松手不会误开对话。

快速拖动曾暴露跨进程起点采样过晚的问题，已改用经过校验的窗口内按下位置确定起点，后续由主进程读取实际光标计算位移。展开输入时的边缘避让不覆盖宠物逻辑锚点；收起后不会因窗口变宽而跳回其他位置。

### 原角色动作匹配

- 安静待机：`idle`，保留原呼吸、眨眼和眼神。
- 展开输入：`curious`，等待用户输入，不冒充录音。
- 等待模型：`thinking`，使用原项目的思考点变形。
- 获取及分析本次画面：`viewing → searching`，左右观察。
- 实际文字回复：`responding → writing`，原铅笔书写动作。
- 回复正常结束：`feedback → happy`，短暂开心。
- 请求失败：`error → confused`，短暂疑惑。
- 拖动期间：`dragging`，提起动作；松开恢复当前工作状态。

完成和失败反馈约 2.4 秒后恢复；停止立即恢复待机，不触发完成庆祝。动作只在阶段变化时切换，不因每个文字片段反复重启。原创 DotPet 使用相同语义的独立姿态；保留暂停与减弱动画处理。

## 验证结果与证据边界

- **构建**：完整构建与类型检查通过，动作联动后生产渲染包含 30 个模块；构建检查未发现本机学习素材进入产物。静态设计检查未报项。
- **运行时受控测试**：23 项夹具通过，覆盖流式拆包、工具与图片传递、授权拒绝、无密钥、取消、迟到事件、超时、调用上限、截断响应及会话隔离；本轮补充了取得图像后保持观察、拒绝工具时不显示观察的断言。
- **Windows 桌面链路**：曾通过本机受控 SSE 服务完成两次请求，确认模型协议中的工具请求、真实主屏 PNG 返回和图像传回，`toolRequested`、`imageReceived`、`pngValid` 均通过。这是固定协议响应测试，不是真实模型识图或分析效果验收。
- **拖动实测**：便携版窗口随鼠标准确移动 `(-120,-80)`，松手保持原模式，随后单击正常收起且保持宠物位置；原黑色角色也准确完成 `(-80,-60)` 拖动及单击收起。
- **动作联动**：独立本机受控事件页使用实际 DemoApp/AgentConversation，验证思考、观察、书写、完成、失败、新请求重置和真实停止按钮恢复；该页不连接模型、不读取屏幕、不保存配置。四动作预览是受控状态图，不是模型执行证据。
- **交付状态**：原角色入口已重载，新便携包已生成。便携启动及拖动有前一版的 Windows 证据；动作联动版已构建打包，尚未逐项重跑新版便携包的完整流程，不能合并声称全部实机验收完成。
- **真实服务**：尚未使用用户自己的视觉与工具模型完成端到端验收；没有可据此认定的真实翻译、报错诊断或自动修复结果。

本次文档整理引用的是上述对话内已执行的验证，没有为纯文档修改重新运行构建、模型或桌面操作。

## 当前没有完成的能力

语音录音、识别、合成与唤醒，OCR，终端执行和文件修改，网页搜索，鼠标键盘接管，外部账户连接，模型长期记忆检索，主动目标跟进与梦游，联想平板配对及 Android/跨设备验收，均不属于已完成的当前主入口。

中途版本曾有多场景与本地资料面板，相关代码保留不等于当前默认产品仍开放这些入口，更不等于已接入对应外部服务。完整 Dot 功能愿景和早期 FE 清单继续保留为规划，不能把预设示例、动画或复选框当真实执行结果。

## 启动与后续接续

本机原角色：双击已有学习素材的工作区最外层 `原角色演示.cmd`，该入口仅适用于本机现有工作区。工程内也可运行 `npm run desktop:dev`；从仓库克隆且没有学习素材时自动使用原创 DotPet。修改桌面主进程或 preload 后需重启。

便携版：本机通过 `npm run desktop:package` 生成后，打开 `outputs/伴屏-Demo-win32-x64/伴屏 Demo.exe`，移动或分享时保留整个目录。便携产物不提交到源码仓库，使用原创角色；原黑色学习角色及本地预览不随便携包分发。

下一步优先使用用户自己的兼容服务，确认图像输入与工具调用，分别测试普通问题不读屏、需要画面时调用工具、画面改变后回答对应变化，以及停止与拒绝授权。随后补多屏/缩放、休眠恢复、屏幕授权重启失效及新版便携包回归。语音和受限执行根据后续范围逐项接入，保持当前极简界面。

关键代码入口：`apps/desktop/src/demo/` 下的 DemoApp、AgentConversation、ModelSettings、usePetDrag；`src/character/study-map.ts` 与 study-loader；原创 DotPet 和 dot-pet.css；`apps/desktop/electron/` 下的 agent-runtime、model-config、screen-capture、screen-tool、main 和 preload。

本地验证与图片位于 `outputs/validation/`、`outputs/preview/`，不进入正式构建。主要预览文件为 `character-work-actions.png`；更细的验证记录见 [Demo 说明](04-dot-demo.md)。
