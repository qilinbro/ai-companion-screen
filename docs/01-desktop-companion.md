## 1. 本次修订：电脑端先独立可用

产品仍叫「伴屏 AI Companion Screen」，目标是一个能延续协作的常伴 Agent。先做 Windows 电脑客户端，让它在电脑上安静待机、理解授权画面、记住用户确认的背景，并执行受限任务；随后将同一个角色、任务与结果延伸到联想平板。平板继续承担电脑旁伴随副屏的最终目标，不要求它成为电脑客户端启动的前置条件。

本方案制定时的早期参考对象为 **Meta Muse** 与 **New Computer Dot**。从 Muse 借鉴持续推进目标、后台任务与结果汇报；从 Dot 借鉴个性化陪伴与协作背景的延续。2026-10-20 用户通过明确网址确认的新参考为 **OpenAI Dots**，与 New Computer Dot 不同，后续又将当前交付收敛为简洁的宠物与模型对话。历史推导保留，具体范围见[会话总结](05-session-summary-2026-10-20.md)，公开资料边界见[参考核实](02-product-references.md)。不复制参考产品的品牌、角色或界面。

相对 v0.1 的建议变更：

- 电脑从“仅提供共享的浏览器控制页”升级为可独立启动的桌面客户端。
- 记忆的基础管理前移，先让用户主动记录偏好与项目背景；模型检索和真正的跨会话使用随后验收。
- 首条真实屏幕问答先在电脑跑通；局域网配对与平板展示后移，但仍保留独立、不可替代的真实跨屏验收。
- 建议先跑通一个受限 Agent 工具，再接语音；这是本轮提出的优先级调整，尚待文档验收。

## 2. “常伴”的具体体验

角色有稳定的名字、语气和轻微动作。用户不需要每次重述项目背景，但能随时查看它记住了什么、为何使用这条记忆，以及如何修改或忘记。

典型目标场景，均为待开发需求：

1. **接着昨天做**：用户说“继续昨天的联想平板项目”，角色依据已保存的项目摘要和真实任务记录恢复背景；缺少记录时直说，不编造昨天的进展。
2. **理解正在看的内容**：用户选择共享窗口后问“这个报错什么意思”，角色获取当前实际画面，给出可见事实、可能原因、排查步骤及缺失日志。
3. **在范围内办事**：用户说“盘点这个项目目录”，电脑弹出目录选择与操作范围，Agent 制定简短步骤、调用只读工具、验证并汇报。
4. **有进展再来找我**：用户收起画布后，已授权任务在进程仍运行时继续；完成、失败或需要输入时出现一条简短通知，点击后回到同一画布。
5. **安静一起工作**：不发任务时角色待机；默认不读取屏幕、不录音、不发起新的模型调用。用户单独开启梦游后才按设定低频观察。

“常伴”不等于全天采集。它的连续性来自用户确认的记忆、明确目标和可核对的任务结果；角色旁白不展示内部推理，也不声称角色具有真实心理活动。

## 3. 主要参考：借鉴功能，保持自己的界面

### Meta Muse：目标能够持续推进

Meta 的官方产品说明介绍了长期目标、任务执行、记忆与授权控制；官方设计文章进一步描述了后台任务、值得打断时才通知、可查看的活动/权限/记忆及丰富产物。这些是公开说明，并非本项目已复现或经过实测的功能。[Muse 产品说明](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)、[Muse 设计说明](https://introducing.muse.ai/)

本项目采用的设计：目标能接着做、执行有结果证据、进展可查、通知有节制、产物在画布中直接使用。第一版只运行一个实际执行任务，新增请求可以补充当前目标或进入等待，不急于复制并发多任务系统。

Muse 的主聊天、侧聊天、Goals/Ideas 等界面不直接移植。本产品保持两个主状态，活动记录、目标细节、权限和记忆都按需展开。

### New Computer Dot：协作背景能够延续

Dot 的历史官方产品页强调个性化理解与建议；隐私资料说明用户可提供笔记、图片、音频、文件、链接等信息，并对额外数据访问保留控制。官网现有停运公告，因此将其作为历史设计参考，不依赖在线服务或可用 API。[Dot 历史产品页](https://new.computer/dot)、[Dot 隐私资料](https://new.computer/privacy)、[停运公告](https://new.computer/)

本项目采用的设计：保留用户主动提供且确认的偏好与背景；从相关记忆中延续协作；支持纠错、忘记、导出。不会把“理解用户”扩展为默认监听、自动建立人格画像，或声称可以无限记忆。查到的官方资料不足以证明 New Computer Dot 具有电脑屏幕观察或桌面工具执行能力。

以上“采用的设计”是本项目的需求推导；不是对参考产品全部能力、底层实现或实际效果的复述。

## 4. 电脑界面：待机角色与单张工作画布

### 待机角色

- 桌面边缘一个可拖动的小角色，呼吸、眨眼、轻动作，默认静音、不抢焦点。置顶可关闭，不默认覆盖全屏应用。
- 点击角色或使用可配置快捷键唤出输入；按 Esc 收回。角色位置按显示器和缩放保存，显示器移除后恢复到可见区域。
- 托盘提供“唤出角色、暂停观察、停止任务、设置、退出”。任务运行时有轻微真实状态提示；没有任务就不显示假进度。
- 没有常驻功能宫格、仪表盘、多列聊天、侧边任务列表或大批状态卡片。

### 单张工作画布

- 从角色展开一张画布，角色留在边缘；文字输入、过程与结果均在同一位置。
- 支持文字、受限 Markdown、代码、图片、步骤与必要按钮。不同产物按顺序排版，不铺成多个独立工作面板。
- 一次只展示一个当前任务。其他等待或历史任务通过按需打开的选择层切换，不常驻侧边列表。
- 运行时显示真实当前动作；仅在步骤可数时显示“2/4 步”，不能用计时器伪造百分比。
- 完成后保留结果，用户决定继续、复制、查看实际产物或回到待机；不因角色归位而丢掉结果。
- 记忆、权限、活动记录与设置使用临时浮层；关闭后回到原画布，不增加第三个常驻主状态。

```text
桌面待机角色 → 点击 / 快捷键 / 任务通知 → 单张工作画布
      ↑                               ↓
      └──────── 用户收起 ───────────────┘

角色动画：待机 / 听取 / 思考 / 说话 / 反馈
任务状态：等待 / 运行 / 完成 / 失败 / 取消
```

动画只是表达，不能证明已录音、已调用模型或已完成任务。未接入真实语音时默认隐藏麦克风；若提供体验入口，明确写“语音演示（未接入识别）”。文字输入可完成相同核心操作。

## 5. 记忆：从第一版建立可管理的连续性

### 三类数据分开处理

- **当前屏幕上下文**：截图、捕获时间、来源与本次问题，只用于相关任务，默认内存保存，结束、超时或停止共享后释放。
- **短期会话**：当前讨论和临时步骤，可清空；默认不把完整对话永久存档。恢复需要的最小任务摘要与日志分开保存，并允许删除。
- **长期记忆**：用户确认的偏好、项目背景与需要延续的进展。存储条目，不默认保存全部聊天、截图、录音或屏幕活动。

第一阶段先实现手动新增、查看、修改、删除和导出。这里只能验收“记忆存储与管理”，不能据此声称模型已经记得用户。第二阶段接通真实模型后，再验收跨会话检索与个性化使用。

### 写入和使用规则

1. 用户说“记住：我希望报错分析先给排查步骤”，系统展示提取条目和保存入口；也可直接在记忆浮层手动填写。
2. 每条记录包括内容、类别、项目范围、来源、创建/修改时间；任务进展链接实际任务结果，不把模型猜测写为事实。
3. 模型提议的记忆先进入待确认状态，不能自动把屏幕内容、第三方文字或推断存成长久事实。
4. 需要回答时只检索相关范围，并可展开“本次参考了哪些记忆”；失效或互相冲突的条目需澄清。
5. 修改和删除后使缓存及相关检索索引失效；删除数据不继续作为活跃摘要输入。手动导出文件不会被假装一并远程删除。
6. 长期记忆是否发给云模型需在模型配置和使用范围中说明；本地保存不等于内容从不外发。

## 6. Agent：持续推进有边界的目标

目标执行固定包含：理解目标 → 制定简短步骤 → 验证权限 → 调用工具 → 检查结果 → 汇报。展示的是可执行步骤、真实事件与结果，不展示模型内部推理。

### 首项真实工具：只读目录盘点

用户通过电脑本地目录选择器授权一个根目录，Agent 在深度、条目数、耗时上限内统计类型、大小与结构。第一版不移动、删除、修改或读取文件正文，不开放任意 shell。

- 工具每次调用复查任务、动作、有效期及规范化实际路径；拒绝路径穿越、符号链接、junction 和重解析点越界。
- 默认在电脑本地盘点。文件名、相对路径、类型、大小等元数据需要发给模型总结时，说明接收方和范围并取得本任务授权；不默认发送绝对路径。拒绝外发仍可显示本地统计。
- 工具返回记录、截断标记、拒绝条目与错误；验证后再给结论。部分失败或超限必须说明范围，不能说“完整扫描完成”。
- 完成必须有实际工具结果。仅生成了一份计划、建议或漂亮画布，任务不能显示“已执行完成”。

指定浏览器页面操作、文件移动整理与代码修改为后续独立工具，每项单独限定范围和验收。查看屏幕的权限不能转成操作电脑的权限；网页、日志、文件或截图中的文字不能授权新操作。

### 任务状态与后台行为

`waiting → running → completed | failed | cancelled`，由电脑运行时维护。事件含任务 ID、运行版本和递增序号，终态不可被旧消息覆盖。等待既可能是排队，也可能缺少权限/用户输入，要显示原因。

- 用户点击停止后显示“正在停止”，中止模型请求与后续工具动作；执行器确认后进入取消。停止与完成竞态按实际事实处理，不假装撤销已发生的操作。
- **收起画布**只改变显示；已授权后台任务可继续，角色或托盘保持真实运行提示。屏幕分享是否继续由独立授权决定。
- **关闭窗口**收至托盘；首次明确解释仍在运行，并提供直接退出入口。后台行为可在设置关闭。
- **退出应用**停止本地观察和执行，保存最小检查点；无法取消的外部请求如实记录。重启显示“上次中断”，不自动重放工具或有副作用的操作。
- **系统睡眠/关机**期间不承诺工作；恢复后重新检查任务和授权，不宣称离线也在执行。
- 不把应用隐藏、托盘驻留、后台执行、开机自启和云端 24 小时服务混为一谈。开机自启默认关闭；第一版不引入云端常驻 Agent。

## 7. 主动协作与梦游分开

### 任务反馈

对用户已发起任务，在完成、失败、需要输入或出现重要变化时通知一次。重复事件去重，普通过程留在画布；不能每一步弹窗、抢焦点或自动出声。

### 目标跟进

用户明确创建目标与跟进规则后，才按时间或真实事件继续。每项跟进保存触发条件、允许动作、任务预算、通知方式和有效期。没有新信息时保持安静；预算用完、权限缺失或多次失败时停止并给出原因。项目背景本身不等于持续执行授权。

首版只支持受控任务和少量用户配置的跟进；不承诺自动规划一切生活事项。用户可以暂停、取消，或要求不再主动建议。

### 梦游模式

独立开关，默认关闭。在已授权来源上偶尔取一帧，生成至多一句角色旁白。观察频率、文字、出声、安静时段可设置；拟提供 2/5/10 分钟间隔，最终按实测调整。

先用本地变化与冷却判断是否值得调用模型；无变化、没有值得表达内容时不输出。运行中的用户任务优先，不把低频旁白变成自动工具操作或持续屏幕记录。

暂停/停止共享、撤销授权、退出、检测到锁屏或睡眠后停止观察；解锁不自动恢复屏幕授权。Electron 提供 Windows 锁屏与休眠事件，但本项目的响应仍需实机验证。[Electron powerMonitor 文档](https://www.electronjs.org/docs/latest/api/power-monitor)

## 8. 工程方案：Windows 桌面壳与可复用运行时

### 拟选技术

- **Electron + React + TypeScript + Vite**：桌面角色窗口、托盘、快捷键、屏幕选择与现有 Node 技术统一。相比纯网页，更适合本轮电脑常伴需求；代价是安装体积和内存更高，需实测而非承诺轻量。暂不增加 Rust/Tauri 或 3D 引擎。
- **原创 SVG/CSS 角色**：先验证交互、状态和克制的动效，不依赖第三方角色素材。
- **共享 host 运行时**：模块负责模型、权限、任务、工具、记忆和主动规则；桌面使用受控 IPC，不在首版默认开放局域网端口。平板接入时再增加 HTTPS/WSS 传输适配。
- **模型适配器与内置 fetch**：接口按实际提供者验证图像、文本增量、STT、TTS 与取消能力；不假设所有“兼容接口”都能接收截图。
- **存储适配器**：第一阶段小规模数据使用单写入者的本地 JSON 与原子替换，分别保存设置、确认记忆和最小任务摘要；需要结构化检索/迁移时再切 SQLite。不默认引入向量库和重型 Agent 框架。
- **运行时参数校验**：IPC、后续网络消息、工具参数都需校验，拟使用 zod；TypeScript 类型不能充当授权控制。

历史记录：早期代码检查曾在 Linux arm64、Node.js `v24.22.0`、npm `11.19.1` 环境进行，当时缺 DISPLAY/GTK，无法启动窗口。这不是当前 Windows 交付的验证结论；2026-10-20 已另有 Windows 启动、拖动、界面与构建证据，见[会话总结](05-session-summary-2026-10-20.md)。不同开发环境及 Electron 内置 Node 的行为仍须分别核对，不能相互代替。

### 进程与权限边界

```text
电脑 React 界面：待机角色 / 单张工作画布
       │ 仅允许列出的操作
       ↓ preload + 受控 IPC
Electron 主进程：窗口 / 托盘 / 本地授权 / 捕获源选择
       ↓
Host 运行时：目标与任务 / 权限检查 / 模型适配 / 记忆 / 主动规则
       ├─ 模型服务：仅发送本任务获准内容
       ├─ 工具执行器：仅在获准目录 / 页面范围
       └─ 本地数据：用户数据目录，不在源码仓库

后续平板 → 配对后的 HTTPS/WSS → 同一 Host 任务与角色状态
```

运行时逻辑先可独立测试；长任务和工具执行放到可停止的工作进程，不能阻塞窗口主进程。主进程批准能力范围，Host 每次调用复查；界面、模型与外部页面都不能直接访问任意文件、密钥或命令执行。

按照 Electron 官方建议启用渲染进程隔离、沙箱和限制性 CSP，关闭渲染层 Node 集成，验证 IPC 发送方并只暴露所需方法；任务产物和外部网页不得取得桌面桥接能力。远程网页不加载进有管理能力的界面。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

### 真实画面如何获取

电脑用户在本地可信选择器明确选择屏幕/窗口，主进程绑定该来源和权限版本，再按任务需要捕获。Electron 提供桌面来源枚举与捕获接入，但官方例子里的“选择第一个屏幕”不能用作本产品的授权方式；也不保证 Windows 一定会自动弹出系统选择器。[Electron desktopCapturer 文档](https://www.electronjs.org/docs/latest/api/desktop-capturer)

区域能力通过已授权来源内的明确框选与裁剪实现；仅裁剪区域传给模型。它不是操作系统级独占区域权限：原始流仍可能在电脑捕获模块内存在。切换来源、尺寸或缩放变化时使裁剪范围失效并重新确认。

默认一次问题取一帧；需要更新或真实工具步骤确有需要时才请求新帧。捕获带时间、来源、尺寸、captureId 和授权版本。暂停后禁止新取帧/上传，作废排队画面；停止则结束轨道并清空瞬时数据。不能只暂停预览就声称停止捕获，也不能把旧帧当当前屏幕。

屏幕获取、向模型外发、麦克风、工具和梦游分别有权限状态。截图文字属于外部数据。密钥只在受信任电脑运行时，开发用本地环境配置，分发版使用经验证的系统凭据保护方案；不注入前端、不进日志或 Git。

## 10. v0.2 开发阶段建议

### 第一阶段：可运行的 Windows 电脑客户端

全部待开发：

- [ ] D1-01：工程骨架、Electron 启动、依赖锁定、类型检查与实际构建。
- [ ] D1-02：角色待机、展开单画布、文字输入、复制/保留结果、键盘可操作与减弱动画。
- [ ] D1-03：托盘、可配置快捷键、位置恢复、收起/关闭/退出的明确行为；不自动安装后台服务。
- [ ] D1-04：真实 IPC 往返与错误状态。无模型时显示“本地输入已收到，未调用 AI”，不能用固定回复冒充聊天。
- [ ] D1-05：用户手动确认的记忆增删改查和导出，重启后可读取；保存失败如实显示，删除后不再读取。
- [ ] D1-06：任务状态与取消通道、最小活动记录；测试任务必须标为“本地连通性测试”，不伪装工具任务。
- [ ] D1-07：在 Windows 实际启动并验证打包产物。目标为 `.exe` 桌面程序/安装产物，具体打包器与签名方案实施时核实；不把浏览器预览当桌面客户端交付。

验收：角色和画布可用、真实 IPC 有回执、托盘可恢复也可真正退出、记忆经重启保留/修改/删除有效、没有网络或密钥时仍可运行这些基础能力。第一阶段通过也只算“桌面交互与存储基础”，不算完成常伴 Agent MVP。

### 第二阶段：真实对话、屏幕问答与记忆使用

- [ ] 配置真实文本/图像模型，说明外发范围，支持实际文本增量与取消；缺配置和调用失败不返回预写答案。
- [ ] 使用用户共享的真实窗口回答“翻译当前画面”“分析这个报错”，按需更新画面，正确处理暂停与停止。
- [ ] 回答能检索相关已确认记忆，并允许查看使用来源；新会话中纠正/删除记忆后不继续沿用旧信息。
- [ ] 处理模糊画面、过期帧、缺少日志、图像能力不支持、上游中断与权限撤销。

验收：现场修改真实窗口中的英文与随机标记，重新取帧后结果随之改变；报错来自一次真实程序输出，缺日志明确指出。记录 captureId、时间、来源、模型/请求 ID（如有）与人工核对。这只算“桌面真实屏幕链路”，不能声称跨设备已完成。

### 第三阶段：受限 Agent 工具与目标跟进

- [ ] 跑通只读目录盘点：理解、步骤、授权、实际执行、验证、汇报及运行中停止。
- [ ] 收起画布后已授权工作按设置继续，完成或需要输入时只通知一次，点击恢复真实结果。
- [ ] 支持一项用户明确设置的目标跟进规则，控制预算与重复通知；任务退出/失败/恢复状态准确。

验收：允许目录可读、越界与链接逃逸被拒绝、工具失败不转成功、停止后无后续动作；目标跟进有实际触发和工具依据，无变化时不扰动。

完成前面三阶段并通过真实模型、屏幕和工具验证后，才称“电脑常伴 Agent 最小可用版本”。高级浏览器控制、多 Agent 并行与广泛应用操控不在该承诺内。

### 第四阶段：真实语音输入、回复与打断

- [ ] 电脑端真实麦克风 → STT → 同一任务通道 → 文本/语音输出，文字仍可完成全部核心操作。
- [ ] 听取/思考/说话状态对应真实采集、请求与播放；音频失败或权限拒绝有可见处理。
- [ ] 打断停止播放、清空音频队列并中止关联生成，迟到音频/文本不进入新轮次。

验收以实际声音输入、识别文本、真实合成音频和一次有效打断为准；不默认开启持续监听。是否支持边播边说、唤醒词与平板语音，分别实测后声明。

### 第五阶段：局域网平板、梦游与联想适配

- [ ] 短时一次配对码、电脑确认、设备角色、可撤销会话、重连与任务版本同步；同一目标由同一个运行时负责，避免两端重复执行。
- [ ] 同一角色/记忆和任务延伸到平板，两端可输入，结果保留。重复命令和过期事件拒绝；默认只在当前用户选择的一端播放语音。
- [ ] 提供可信 HTTPS/WSS，证书匹配实际域名/IP并被平板信任。电脑本地捕获与平板麦克风的安全条件分别检查，不能把 localhost 例外套到 LAN HTTP。
- [ ] 真联想平板完成“电脑实际画面 → 真实模型 → 平板画布”硬验收，之后再测试梦游模式与目标设备安装包。
- [ ] 梦游默认关，观察、旁白与静默均有真实依据；平板后台/锁屏行为单独实测，不承诺一直在线。
- [ ] 核实型号、Android/浏览器/WebView、网络、音频、旋转、功耗、安装签名与权限；浏览器通过不等同于 Android APK 适配。

比赛方向、官方设备要求和天禧文档/访问资格继续待核实。电脑版先交付不等于已经满足“联想平板提升学习/工作效率”的完整参赛验收。

## 11. 首个真实跨屏功能的独立验收门槛

这项要求不因电脑优先而降低，也不能被第二阶段桌面自测替代：

1. 一台真实电脑和一台真实联想平板在同一局域网，实际完成配对与安全连接。
2. 电脑用户选择真实窗口，明确屏幕与图像处理授权；窗口显示当场写入的英文和随机标记。
3. 在平板输入“翻译当前画面”，电脑本次真实取帧并调用图像模型，平板显示对应内容。
4. 电脑修改内容，平板请求更新，核对新 captureId 与新结果；再用实际错误输出验收报错分析。
5. 暂停/停止/撤销授权后，平板请求不会产生新取帧、图像外发或模型调用；迟到结果不覆盖取消状态。
6. 核实画面模糊、缺日志、断连、模型失败和停止任务的结果；未通过项明确记录。

验收记录包括设备与软件版本、代码版本、网络方式、来源/时间/尺寸/captureId、模型/请求 ID（如有）、实际结果核对和失败场景。默认仅保留最小元数据，用户单独选择后才保存必要截图/录屏并可删除。模型 Mock、固定图片、上传示例图、模拟平板或角色动画均不能替代。
