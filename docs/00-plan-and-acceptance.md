## 对 v0.1 的变更

- 原浏览器共享控制页方案升级为 Electron 桌面客户端提案；渲染界面仍采用 React/TypeScript。
- 基础记忆管理前移；真实模型检索与跨会话使用另行验收。
- 先验收桌面真实屏幕链路，再验收 LAN 平板，不把两者混为一项。
- 建议 Agent 工具先于语音，平板与梦游后续接入。此顺序调整待本轮文档验收。
- [v0.1 已归档](archive/00-plan-v0.1.md)，仅供历史对照，不作为当前实现基线。

## 分阶段完成依据

1. **桌面基础**：Windows 实际启动；待机/单画布、托盘、真实 IPC、手动记忆增删改查/导出及重启验证。不能称模型记忆或 Agent 已实现。
2. **真实理解**：真实文本/图像模型，使用本次授权窗口取帧；现场改内容后结果对应变化；缺信息明确指出。跨会话检索已确认记忆且可纠错删除。
3. **受限执行**：用户指定目录的只读工具实际返回，越界拒绝、停止有效、验证后汇报；目标跟进有真实事件与通知去重。
4. **真实语音**：实际录音、识别、合成与中断验收；文字操作保留。
5. **实际跨屏**：真实联想平板配对，平板提问触发电脑当前取帧和真实模型，平板画布显示结果；再验收梦游与目标设备适配。

前三阶段通过后才称“电脑常伴 Agent 最小可用版本”。完成跨屏、Android 安装适配、天禧接入与比赛符合性是不同结论，必须分别有证据。

## 当前检查事实

- 本次对话在 Windows 图形桌面完成了源码启动、便携启动、主屏 PNG 受控链路和原生拖动检查，早期 Linux 无 GUI 记录只保留为历史。
- 当前有文字输入、单画布、模型设置、流式对话、停止/复制、一次主屏工具、拖动与角色动作联动。模型密钥由主进程管理，屏幕外发授权只在本次运行有效。
- 动作联动后的完整构建通过，生产渲染 30 个模块；23 项运行时夹具通过。动作切换另由实际前端组件的本地受控事件页验证。
- 本机 SSE 服务验证了真实图片传递，不等于真实模型理解效果。用户兼容服务尚未完成端到端验收；语音、终端执行、模型长期记忆、外部连接与平板没有本轮完成证据。
- 最新动作联动便携包已生成；此前便携启动/拖动证据与新版完整回归分别记录，不混为同一次验收。详细边界见[当前 Demo 验证状态](04-dot-demo.md#当前验证状态)。

## 现在如何使用

使用工作区最外层 `原角色演示.cmd`，或在工程目录运行 `npm run desktop:dev`，可打开本机原角色。便携版从 `outputs/伴屏-Demo-win32-x64/伴屏 Demo.exe` 启动，使用原创角色。输入与设置、所需模型能力、密钥和屏幕授权见[README](../README.md)；开发命令仍需图形桌面与 Node.js >= 22.12。后续交付继续分别记录实现、启动、验证和未完成项。

下一步优先用用户实际兼容服务验证图像/工具能力及停止和拒绝路径，补充多屏/缩放、生命周期和新版便携回归；联想平板、LAN、官方比赛及天禧资料保留为后续独立条件，不阻止当前桌面 Demo 的独立改进。
